# Day 9: MariaDB Troubleshooting

### Task Overview
An application in the Stratos Data Center faced issues connecting to the database (MariaDB). The MariaDB service was shutdown and could not be simply turned on. This required some digging into the root cause. Upon SSHing into the correct server, I ran the below command to check the status of the service and found it was dead: 

```
sudo systemctl status mariadb
```

I then tried to simply start the service with this command which failed, but gave me another one to try to dig deeper:

```
sudo systemctl start mariadb 
```

To view more details about this particular service:
```
sudo systemctl status mariadb.service
```
Which then generated an error log which included the following snippet:
```
Process: 2361 ExecStart=/usr/libexec/mariadbd --basedir=/usr $MYSQLD_OPTS $_WSREP_NEW_CLUSTER (code=exited, status=1/FAILURE)
Main PID: 2361 (code=exited, status=1/FAILURE)
```
Upon researching this, I found that this is generally a permissions issue. To determine ownership of mysql directory, I ran this command (attached is the output too):
```
sudo ls -la /var/lib/mysql
total 110652
drwxr-xr-x 1 root  mysql      4096 Feb 17 19:59 .
drwxr-xr-x 1 root  root       4096 Aug 29 06:05 ..
-rw-rw---- 1 mysql mysql     24576 Feb 17 20:04 aria_log.00000001
-rw-rw---- 1 mysql mysql        52 Feb 17 20:04 aria_log_control
-rw-rw---- 1 mysql mysql       976 Feb 17 19:59 ib_buffer_pool
-rw-rw---- 1 mysql mysql 100663296 Feb 17 20:04 ib_logfile0
-rw-rw---- 1 mysql mysql  12582912 Feb 17 19:59 ibdata1
-rw-rw---- 1 mysql mysql         0 Feb 17 19:58 multi-master.info
drwx------ 2 mysql mysql      4096 Feb 17 19:58 mysql
-rw-rw---- 1 mysql mysql        16 Feb 17 19:58 mysql_upgrade_info
drwx------ 2 mysql mysql      4096 Feb 17 19:58 performance_schema
```
At the top, we can see that the parent directory (.) is owned by root, whereas the files and subdirectories are owned by mysql as they should be. We needed to change the ownership over to mysql with:
```
sudo chown -R mysql:mysql /var/lib/mysql
```
Having changed ownership was the most important part, but we also had to examine and change permissions for the directories and files to follow best practices. 
```
sudo find /var/lib/mysql -type d -exec chmod 750 {} \;
sudo find /var/lib/mysql -type f -exec chmod 640 {} \;
```

This then allowed the MariaDB service to be started up and that passed the lab!
